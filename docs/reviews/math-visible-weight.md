# 网页公式加厚实际生效修复

日期：2026-11-23。

## 已确认的原因

PR #132、#133 曾用网页 CSS 的 drop-shadow 增强公式边缘；随后 PR #134 修复字体与斜体校正时，将该规则改为 `filter:none`。main 的 `979f44f48460601e2545a96b7b2d4de5e6f01b88` 已由 Pages 成功部署，线上公式 SVG 也没有加厚轮廓。因此“再次加粗后仍与此前相同”有明确的代码原因，不能归咎于用户设备或单纯要求清理缓存。

公式是独立 SVG 图片，网页上的 `font-weight`、`-webkit-text-stroke` 无法改变其内部路径。本次在导出阶段给 SVG 字形添加只在屏幕生效的 0.18 PDF pt 居中轮廓（20px 公式约为 0.36 CSS px 总宽，每侧约 0.18px），保持清晰边缘，不叠加阴影。沿用原 CM bea 字形、TeX 斜体校正、公式位置、字号、上下标比例、真实基线、3pt 防裁切出血与长公式滚动。

字形路径使用直接类选择器；不能用依赖 `defs` 祖先的选择器，因为 `use` 实例中的字形位于独立影子树。浏览器实测排除了“源码已写样式、实际像素仍未变化”的情况。普通公式轮廓与填充同为主题正文色；显式颜色继续传递给对应字形。分数线等非字形线段保留 TeX 线宽。

公式导出目录同时包含正文颜色和外观代码的 SHA-256 指纹。数学内容未变化时可继续复用原生 TeX 编译缓存，但部署后的 HTML 引用新的图片地址，避免继续使用旧的较细资源。打印媒体仍使用原生轮廓；现有下载 PDF 未重生成。

## 已完成的样本核验

- 同一公式在 19、21、36px 下，用浏览器真实 `img` 加载新旧 SVG，按 3 倍分辨率采样透明度覆盖面积。导数、独立字形、积分与上下标四组、共十二个样本的墨量增加约 30.3%—33.3%。这是像素覆盖量的比较，不是 CSS 字重数值。
- 同屏目视检查 `f'(x)`、二阶和三阶导数、`f/r/0`、`f_n^2(x)`、积分与分式；加厚可见，撇号与括号仍分开，独立字形完整。
- 几何回归检查确认路径、位置、宽高、viewBox、变换及分数线宽均保留；原生 Beamer 字体/度量、fontspec 先加载、导数字形位置和出血测试通过。
- Chromium 验收不等同于 iOS Safari 真机测试。
