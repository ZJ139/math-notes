# CM bea 原生字形与导数间距修复

日期：2026-11-22。

## 原因与范围

用户提供的第一张图是较早的 Beamer / Computer Modern 公式风格。当前共享配置却把数字与纯拉丁字母绑定到正文的 `encodingdefault` / `sfdefault`；在 fontspec 环境下实际采用 TU 编码的 Latin Modern Sans Oblique。该 TU 配置中的斜体 f 后没有实际留下经典 TeX 斜体校正的间隙，f 与导数撇号发生碰撞；同时 fontspec 又把普通括号、数字等部分符号改回 CMR，与预期的 Beamer 配置不一致。先前的屏幕 drop-shadow 加粗扩大了笔画周围的暗边，进一步减小了视觉间隙；它不会改变真实字宽或修复字偶间距。

共享 `cm-bea.sty` 现固定为经典 OT1 / cmss、cmssi 数学字体及原生 TeX 字体度量。fontspec 继续提供 Fandol 等正文字体，但通过其 no-math 选项停止替换数学符号；即使正文先加载了 fontspec，仍采用相同的数学字形与间距。网页公式去掉 drop-shadow，使用未经描边或模糊的原始轮廓。

本次修复覆盖全站网页公式，包括行内与行间、讲义、文章和题解。标准 LaTeX 输入、辅助 MathML、字号、基线处理、四边 3pt 防裁切出血及独立横向滚动保持原有实现。已发布的下载 PDF 不重新生成；后续从共享配置生成的文档使用修正后的字体。

## 验证记录

- 将包含 f(x)、一至三阶导数、f 的平方、下标、三角函数、希腊字母与积分的相同公式，分别放入经典 Beamer 和共享公式渲染器；尺寸与字体清单一致。
- 单独核查先加载 fontspec、再设置正文主字体和无衬线字体的情况，数学字体仍为 CMSS / CMSSI，f 的原生斜体校正为正值。
- 保留短字形完整性、真实尺寸与基线、批量与单条渲染一致性测试。
- Chromium 中检查相同公式与《Wirtinger不等式及其推广》的背景段落：导数撇号与 f 分开，普通括号和 f 不再拥挤；390px、768px iframe 中 21 张公式全部加载，文档无横向溢出，长公式可在自身区域横向滚动。
- Chromium 验收不等同于 iOS Safari 真机测试。

在同字号的实际 PDF 字符位置中，旧配置的 f 与其右侧撇号起点相距约 3.05 PDF pt；经典 CM 配置相距约 5.21 PDF pt，恢复了约 2.16 PDF pt 的原生间隙。普通 f(x) 的左括号也得到相同的校正。
